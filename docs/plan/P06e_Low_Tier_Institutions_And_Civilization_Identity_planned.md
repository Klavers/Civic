# P06e — 저티어 제도와 문명별 고유 제도

> **Status**: planned
> **Parent**: [P06 Umbrella](./P06_Player_Choice_Governance_Navigation_Accessibility_Umbrella_planned.md)
> **GitHub issue**: [#53 P06e: 저티어 제도와 문명별 고유 제도](https://github.com/Klavers/Civic/issues/53)
> **제도 설계 정본**: [SUG10](../suggestion/SUG10_정치와_사회_체계.md)

## §0 Context

현재 `governance.politics`는 정부·유권자·복지·교육·경제의 5개 그룹에서 정확히 하나를 활성화하고 개혁 과정으로 교체한다. 구조는 확장 가능하지만 원시 기본값 외 선택지가 대부분 중후반에 있어 저티어 플레이가 수렴한다. 시작 문명 metric은 존재하나 문명별 초기 제도와 고유 제도의 명시적 데이터·표시 계약은 없다.

## §1 목표 (Goals)

1. 기존 5개 그룹과 단일 활성·개혁 과정을 유지하면서 원시부터 공통 선택지를 제공한다.
2. 고대 이후에도 상위교체가 아닌 조건부 횡적 선택을 확장한다.
3. 모든 시작 문명에 최소 1개 고유 제도를 제공한다.
4. 시작 문명·제도 모듈 동시 ON에서만 문명 연계를 활성화한다.

## §2 비목표 (Non-goals)

- 별도 문화·생활양식 모듈이나 여섯 번째 그룹을 만들지 않는다.
- 모든 문명의 최종 수치·플레이버를 이번 plan에서 확정하지 않는다.
- 다른 문명의 고유 제도를 현재 런의 개혁 목록에 표시하지 않는다.
- 복수 제도를 한 그룹에서 동시에 활성화하지 않는다.

## §3 데이터·밸런스 계약

- 공통 제도는 원시부터 그룹별 분기를 제공하고 고대에 선택지를 추가한다.
- 후기 제도는 새로운 장단점·운영 축을 제공하며 저티어 제도를 완전 대체하지 않는다.
- `institutions.csv`는 적용 문명, archetype tag, provisional 상태를 표현한다.
- `civilization_start.csv`에 `kind=institution`을 추가해 문명별 초기 활성 제도를 지정한다.
- 고유 제도는 해당 시작 문명에서만 목록에 표시하고 시대·기술·경제 조건 전에는 잠금 사유를 표시한다.
- 각 문명은 최소 1개 고유 제도를 가지며 일부 문명은 원시 고유 제도로 시작한다.
- 시작 문명 모듈이 OFF이면 공통 제도만, 제도 모듈이 OFF이면 제도 효과 없이 시작 문명 효과만 적용한다.
- AI 초기 효과·비용·설명은 실제 작동하지만 `provisional`로 표시한다.
- 공통·고유 제도 모두 장점과 실제 비용/약점을 가져야 하며 완전 상위호환을 금지한다.

## §4 구현 단계 (Steps)

1. 공통 원시·고대 제도 inventory와 플레이양식 tag를 정의한다.
2. 모든 문명의 초기 제도와 고유 제도를 provisional 데이터로 작성한다.
3. 시작 문명+제도 integration과 `kind=institution` bootstrap을 구현한다.
4. 현재 문명에 해당하는 고유 제도만 snapshot/UI 후보에 포함한다.
5. 국가 허브의 제도 탭에서 그룹별 단일 활성·개혁·잠금 사유를 표시한다.
6. 대표 문명·제도 조합의 성장 곡선과 상위호환 여부를 테스트한다.

## §5 검증 (Verification)

- [ ] 각 그룹에 정확히 하나의 활성 제도만 존재한다.
- [ ] 공통 원시 분기와 고대 확장이 문명 모듈 OFF에서도 작동한다.
- [ ] 모든 문명 정의에 고유 제도가 최소 1개 연결된다.
- [ ] 해당 문명의 고유 제도만 표시되고 다른 문명 전용 항목은 숨겨진다.
- [ ] 시작 문명·제도 단독 및 pairwise ON의 fallback이 정확하다.
- [ ] 대표 시나리오에서 고유 제도가 공통 제도의 모든 장점을 동시에 지배하지 않는다.

## §6 리스크 (Risks)

| 리스크 | 영향 | 완화 |
|-|-|-|
| 16개 고유 제도의 콘텐츠 폭증 | 품질·밸런스 편차 | provisional 표시와 별도 정식 패스 |
| 문명 고정 빌드 발생 | 자유 조합 약화 | 초기값만 다르게 하고 공통 제도로 자유 개혁 허용 |
| 다른 문명 전용 항목 노출 | 목록 과밀·달성 불가 혼란 | applicability filtering과 PlayMode 검증 |
